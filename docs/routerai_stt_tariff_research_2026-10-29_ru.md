## Установленные факты

1. Обе официальные модельные карточки показывают ровно аудиооперацию с оплатой
   длительности; примеры используют точные model ID и /api/v1/audio/transcriptions.
   Следовательно, прежняя формулировка «нет подтверждения API вообще» слишком
   сильна. В endpoint metadata API не указан, но документация модельного API есть.
   Существующий валидатор пока не умеет учитывать это отдельное доказательство.
2. У Whisper каталог/endpoint metadata одновременно содержат равные положительные
   prompt и seconds с различными units: token и second. Completion равен нулю,
   supported_apis пуст. Эти исходные поля сохранены, не переименованы и не удалены.
3. Сайт показывает ставки за минуту с округлением. Точную RUB/second нужно брать
   из API, а не восстанавливать из округлённой цифры карточки. Цена резервного
   маршрута может превышать основную в несколько раз.
4. Живой каталог содержит 583 модели. Конфигурационного
   qwen/qwen3-asr-flash-2026-02-10 по-прежнему нет; обнаружены другие ID
   qwen/qwen3-asr-0.6b и qwen/qwen3-asr-1.7b. Они не подставляются в config
   автоматически и не объявляются эквивалентной заменой.

Ставка, округлённая до 0,02 ₽/мин в карточке, не является верхней ценой всех маршрутов.

## Что остаётся предположением

Равенство prompt и seconds у этих моделей вместе с единственной аудиооперацией
на сайте согласуется с предположением о совместимом дублирующем поле. Это пока
не доказательство того, что prompt никогда не участвует в счёте. Нельзя применять
правило «удалить prompt у любого STT»: живой microsoft/mai-transcribe-1.5 имеет
разные prompt и seconds (сохранён как контрпример в JSON исследования), а другие
модели распознавания используют только токенные цены.

Документация [Groq](https://console.groq.com/docs/speech-to-text) устанавливает
для прямого Groq API минимум оплаты 10 секунд. Это причина проверить короткие
записи, но не готовое правило RouterAI: посредник может тарифицировать иначе.
USD-ставки прямых DeepInfra/Groq/Together не подменяют RUB-тариф RouterAI.
В открытых просмотренных документах RouterAI точное правило минимума и округления
для каждого маршрута не найдено. Отсутствие найденного правила не означает 0.

## Минимальная недостающая проверка

Только оператор с доступом к существующей SQLite может прочитать уже сохранённые
числовые сведения. Для него подготовлены:

- [scripts/inspect_unbazar_stt_costs.py](../scripts/inspect_unbazar_stt_costs.py) —
  ограниченный SELECT метаданных, соединение mode=ro, query_only=ON, без сети;
- [задание RAI-113-ARAGORN-01](tasks/RAI-113-ARAGORN-01_ru.md).

Скрипт выбирает не более 200 успешных Whisper-наблюдений: фактический model ID,
сообщённые cost/duration и дату. Не выбирает transcript, file/chat/user/job ID,
ключи, raw response или журналы. Старый REAL помечается approximate; если есть
точный cost_rub TEXT, используется он. Это сведения успешного ответа, а не
подтверждение выписки/маршрута или разрешение на новую оплату.
Дополнительная проверка старого кода main unbazarbot по ревизии
2cb0965f2193e225c03ac4c9c9c6450c591df698 обнаружила: STT-адаптер сохранял
usage.duration/duration_seconds, но не usage.seconds. Поэтому поле фактической
длительности в старой базе может быть пустым. Инструмент сохраняет такой факт,
а operational_reserved_seconds из paid_calls показывает отдельно, без выдуманного
расхода за фактическую секунду. Этот резерв отражает Telegram-метаданные либо
максимум конфигурации, а не точную длительность аудио или биллинга.
Существующая согласованная копия предпочтительна, если подходит по дате.
Новые копии рабочей SQLite, перенос базы и остановка службы не нужны.

Я сам подготовил и испытал инструмент; агенту не поручаются разработка, тесты,
публичный поиск, обновление GitHub или выбор тарифной политики. Инструмент прошёл 9 отдельных тестов на искусственной SQLite. Общий
python tests/run_migration_ci.py: 350 тестов, успешно, 5 пропусков; py_compile
успешен. Проверены: права вывода, отсутствие экспорта содержимого,
REAL/TEXT, WAL, пропущенная БД, лимит и некорректные числа/даты.

## Следующее решение по результатам

Сохранённые расходы могут показать зависимость от длительности, минимум на
коротких записях или противоречие гипотезе дублирования. Без маршрута и курса на
момент исполнения они не дают точного подтверждения нынешней ставки и не могут
восстановить неизвестные токены. Результат может оказаться недостаточным — это
допустимый итог; недостающие данные перечисляются явно.

По совокупности публичных и локальных наблюдений следующим отдельным изменением
можно рассмотреть узкое версионное правило нормализации только проверенных
Whisper ID/операции, с исходными полями, источниками доказательств, тестами и
проверкой изменения набора компонентов. Одного supported_apis=[] недостаточно
для вывода о фактическом отсутствии API; одного совпадения цен недостаточно для
удаления компонента. Общие проверки не ослабляются, Qwen не заменяется догадкой.
