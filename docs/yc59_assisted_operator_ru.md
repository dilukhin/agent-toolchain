# YC59: управляемый пакет операторской оболочки

Оболочка переносит проверенную автоматизацию R11b в штатную поставку. Она
передаёт заранее подготовленные данные владельца и строки административной
проверки до короткого окна ожидания, оставляя точную фразу согласия человеку.
Владелец разрешений, Ledger, native veto, состав трёх getters и их таймеры не меняются.
[Принятая приёмка R11b](yc59_r11b_accepted_2026-11-17_ru.md) сохраняет свою область.

## Подготовка пакета

Штатный `toolchainctl yc-owner apply` после обновления ядра возвращает прежний
native seed и дополнительный объект `assisted_operator`. В нём указаны каталог
пакета, его идентификатор и хеш `launch.ps1`. Команда только размещает проверенные
данные: она не запускает владельца, не повышает права, не читает токен и не
выдаёт согласия. Повторная подготовка проверяет все байты, общий замок и полный
журнал; неизвестное содержимое или незавершённый журнал вызывают отказ.
Прежние пакеты сохраняются.

Одинаковый пакет копируется в личные профили уже выбранных владельца и агента.
Вход владельца должен быть отдельным интерактивным сеансом; `runas` этого не
заменяет. Для текущего принятого R11b ничего повторно запускать не требуется.
Прежние отчёты и отметки не удалять и не переносить ради разрешения нового запуска.

Первоначальное доверие задаётся независимо опубликованным хешем, а не ответом
агента или файлом pins из копируемого каталога. Хеш запуска этого выпуска:

`f7571cec0c4fe8dc05ccad2b7db0479765c9f09893027a6476e4ea9bcb3cb015`

В новом системном Windows PowerShell 5.1 с `-NoProfile` один раз прочитать
`launch.ps1`, проверить SHA-256 и исполнять именно прочитанные байты из памяти.
Оболочка дополнительно проверит все закреплённые файлы, удерживая их от записи,
а каталоги — от переименования. Нельзя проверять один файл, затем исполнять
непроверенные байты по изменяемому пути.

## Параметры размещения

Параметры берутся из уже принятых наблюдений и решения владельца до Run.
В пакете нет машинных SID, имён пользователей или путей конкретного стенда.

| Параметр | Источник и проверка |
| --- | --- |
| `OwnerSid`, `AgentSid`, `AdminSid` | Три различные существующие локальные учётные записи. Владельца и агента дополнительно проверяют ОС и native seed; административный помощник сверяет настоящий SID и elevation. |
| `OwnerProfile` | Канонический локальный путь, совпадающий с ProfileList ОС для OwnerSid. Выпуск и результаты выводятся из него. |
| `ClientPython`, `ClientPythonSha256` | Принятые точные путь и байты интерпретатора клиента; это не Python защищённого владельца. |
| `InputRoot` | Уже подготовленная закрытая передача формата `yc59-dima-inputs/v1`: admin/SYSTEM FullControl, владелец ReadAndExecute, агент доступа не получает. Имя `dima_sid` в историческом формате означает выбранного администратора. |
| `PackageRoot`, `ExpectedLaunchSha` | Личная копия точного пакета и внешний хеш запуска. |

Оболочка читает существующий подготовленный набор. Создание/обновление токена,
пользователей, изменение групп и существующих ACL не входят в её apply. Если
набор отсутствует или не соответствует проверяемым правам, работа останавливается.
Данные ресурсов и токен не поступают из общей папки координации. Доверенные
параметры передаются помощникам из проверенного запуска, а не из JSON агента.

Команда ниже — форма запуска для уже заполненного локального словаря `$settings`.
Он содержит параметры из таблицы; секретов в нём нет. Реальные значения в GitHub
или чат не передавать. `$role` равен `AgentSetup` в сеансе агента или `Owner`
в сеансе владельца. `$package` указывает личную копию пакета.

```powershell
$expected = 'f7571cec0c4fe8dc05ccad2b7db0479765c9f09893027a6476e4ea9bcb3cb015'
$bytes = [IO.File]::ReadAllBytes((Join-Path $package 'launch.ps1'))
$hash = [Security.Cryptography.SHA256]::Create()
try { $actual = ([BitConverter]::ToString($hash.ComputeHash($bytes))).Replace('-','').ToLowerInvariant() }
finally { $hash.Dispose() }
if ($actual -cne $expected) { throw 'YC59_LAUNCH_CHANGED' }
& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString($bytes).TrimStart([char]0xFEFF))) `
    -PackageRoot $package -Mode $role -ExpectedLaunchSha $expected @settings
```

## Порядок и остановка

Сначала `AgentSetup`: до нового запроса он ожидает в прежнем сеансе агента,
не воспроизводит старые записи координации и удерживает исключительный замок.
Затем `Owner`: проверка подготовленного native-выпуска, автоматическая консольная
проба шести вымышленных значений, сверка выбранных ID и обычный UAC выбранного
администратора. После локального RUN помощники передают данные. Владелец читает
окончательный запрос и сам вставляет точную фразу с UUID и нажимает Enter.
Помощник помещает фразу в буфер без истории/облачной синхронизации; не отправляет
её в консоль. Разрешение агента или ответ OpenCode once не заменяют это действие.

Перед первым consume клиент создаёт и сбрасывает на диск исключительную отметку
`read_attempted.json` в своей стабильной области LocalAppData. Даже потеря ответа,
ошибка записи квитанции, перезапуск или новый пакет не удаляют эту отметку.
У владельца прежний native-attempt без подтверждённой отмены также блокирует
новую подготовку. Для новой подготовки допустима только независимая проверка
точного rejected/expired через защищённый канал владельца и закрытие процесса;
автоматического нового consume нет. При consumed или unknown — остановка и разбор.
Переход с частной оболочки R11b также проверяет её прежнюю агентскую отметку:
новый каталог управляемого пакета не даёт обойти старую попытку consume.

Успех требует native exit 0 и совпадения полного содержимого обеих квитанций,
независимо пересчитанного хеша, SID/сеанса/PID и профиля трёх чтений. Частичные
квитанции, повторяющиеся JSON-ключи и несовпадения отклоняются. Собственный
`installed_acceptance=false` пакета остаётся false до отдельной установленной
приёмки нового артефакта. Текущий перенос не требует нового облачного опыта.

Время исходного компонента сохранено: 10 минут на Python владельца, 60 секунд
свежести после последнего ID, до 55 секунд решения клиентом. Старый guard,
политики, PATH и общий Python не подменяются; восстановление не подтверждается.

## Проверка разработки

`python scripts/build_yc59_assisted.py` пересобирает только проверяемые хеши
в рабочей копии. Тесты проверяют точные байты, отказ подмене/частичному журналу,
сохранение прошлого пакета, общий замок, durable-отметку до consume, потерю ответа,
reject-only и сопоставление квитанций. Windows CI дополнительно разбирает
PowerShell, проверяет параметры/права удержанных объектов и ввод шести вымышленных
значений в настоящую консоль. Эти проверки не содержат облачных вызовов,
реального токена или автоматического согласия.
