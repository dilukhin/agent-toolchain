# YC59 R11b: принятая установленная адресная приёмка

17 ноября 2026 года принят результат `PASS_INSTALLED_ADDRESSED_READ` для одного
выбранного Windows-стенда. Через защищённого владельца и отдельный сеанс агента
выполнен один точный запрос с личным согласием: Ledger перешёл в `consumed`,
завершены три логических чтения ВМ, загрузочного диска и снимка. Их связи проверены.
Native-процесс завершился с кодом 0.

Обзор исходных материалов разобрал 22 JSON-файла строгим декодером с отказом
повторяющимся ключам; 21 согласованная проверка прошла. Полное содержимое квитанций
владельца и агента совпало, canonical SHA-256 результата независимо пересчитан.
Сопоставлены точный запрос, хеш операции и настоящий процесс. Одна агентская
квитанция отдельно за доказательство выпуска не принималась. Это обзор переданных
материалов, а не новый удалённый доступ к установленному компьютеру.

Принятый компонент:
`sha256:14f643cb899c6bcec43cb2fa417e952d9c9d1a0ba13c5fb6e23a2d1e9e9ea6df`,
source `opencode_permissions@1f7d89d9a8cd2352c6df865e8915f66171475972`.
Исходный native seed SHA-256:
`6ffaf03f930dae1d40c7d775b74dac9a76113fb11451da14eb5c314427188065`.

R11b исправил чтение консоли: counted-buffer API декодируется строго по счётчику,
проверяется стабильное точное приглашение с завершающим пробелом. На модели API
воспроизведён прежний отказ и проверено исправление; затем успешно завершён
установленный сценарий. Неизмеренное содержимое хвоста Windows-буфера не утверждается.
Автоматизированы передача подготовленных данных и строк проверки прав;
положительная фраза остаётся ручной вставкой владельца. Consume автоматически
не повторяется, включая потерянный ответ и неизвестный исход.

Приёмка ограничена этим адресным чтением. `restore_verified=false`; READY снимка
не доказывает восстановление. Новые мутации, snapshot lifecycle/restore и #55
не разрешены. Исходные false в манифесте компонента и предварительном локальном
статусе сохранены; эта внешняя запись не меняет их точные байты и идентификаторы.
Отдельный Check не входил в итоговый ZIP: достигнутый этап оболочки и повторная
нативная проверка до Python учтены вместе с ранее переданным Check.

SID, пути стенда, ID ресурсов, исходный вывод YC, частные квитанции и архивы сюда
не включены. Принятие записано в [permissions#59](https://github.com/dilukhin/opencode_permissions/issues/59)
и [toolchain#120](https://github.com/dilukhin/agent-toolchain/issues/120).
Облачный запуск и прежние actor/G3/G4-пробники для этой записи не повторялись.

Следующий поставляемый пакет операторской оболочки — отдельный артефакт.
Результат частного R11b не превращает его собственный `installed_acceptance`
в true. Его перенос, проверка параметров, блокировок и консоли описаны в
[инструкции оболочки](yc59_assisted_operator_ru.md).
