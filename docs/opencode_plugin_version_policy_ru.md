# Политика версии OpenCode Plugin API

## Что это за два разных компонента

`OpenCode CLI` и npm-пакет `@opencode-ai/plugin` — разные ресурсы.

- `OpenCode CLI` — исполняемая команда `opencode`. Она может принадлежать Chocolatey, npm, curl-install, Scoop или Homebrew.
- `@opencode-ai/plugin` — библиотека Plugin API, используемая конфигурацией и локальными TypeScript/JavaScript plugins. `agent-toolchain` устанавливает её в `node_modules` каталога OpenCode config через `npm install --prefix <config-dir> ...`; это не создаёт второй `opencode.exe` и не является второй установкой CLI.

Для Windows стандартный config dir — `%USERPROFILE%\.config\opencode`, поэтому управляемый package обычно находится по пути:

```text
%USERPROFILE%\.config\opencode\node_modules\@opencode-ai\plugin\package.json
```

## Выбор версии

Политика `dependencies["@opencode-ai/plugin"]` в `config_data.json` имеет три варианта:

- `latest` (по умолчанию): опубликованная версия из тега npm `latest`, независимо от способа установки OpenCode. Версия разрешается до установки, затем устанавливается точно и проверяется по локальному `package.json`.
- `match-opencode`: точная версия активного OpenCode. Перед установкой `npm view @opencode-ai/plugin@<версия> version --json` должен подтвердить её публикацию. Отсутствие программы, неизвестная версия или неподтверждённый пакет останавливают установку без перехода на другую версию.
- Точная версия, например `1.18.18`: явное закрепление версии.

При нескольких установках OpenCode установка плагина останавливается для всех политик. `check` не устанавливает пакеты и не создаёт каталог конфигурации; повторный `apply` при неизменной целевой версии не переустанавливает пакет. Обновление плагина не обновляет отдельно установленную программу OpenCode.

## Изменение прежнего поведения

Ранее `latest` скрыто означала точное совпадение с версией отдельно установленного OpenCode. Теперь имя политики соответствует её действию. Существующая настройка `latest` при следующем `apply` может обновить плагин до опубликованной версии npm, даже если программа OpenCode старее. Совпадение версий и совместимость при этом не утверждаются: для локальных плагинов, требующих определённой версии API, следует выбрать `match-opencode` либо закрепить проверенную точную версию до обновления.

Настройка проекта не требует переноса состояния или создания новой установки OpenCode.

## Диагностика и краткий итог

Вывод завершается разделом «Итог». Он показывает оставшиеся действия с именами компонентов и конкретными командами, без ограничения количества сообщений. Сообщение об ошибке npm различает отсутствие опубликованной версии, сетевой сбой, отказ в доступе и некорректный ответ. Значения секретов и полный вывод npm в эту диагностику не включаются.

Для проверки политики `latest`:

```text
npm view @opencode-ai/plugin version --json
toolchainctl apply
```

При `match-opencode` сначала проверяются `opencode --version` и публикация соответствующей версии пакета. Повторный `apply` сам по себе не устраняет отсутствие версии в npm.

## Диагностика параллельных CLI

Локальный `@opencode-ai/plugin` в config `node_modules` не считается параллельной установкой CLI. Для поиска настоящих дубликатов `agent-toolchain` отдельно инвентаризирует исполняемые `opencode` в PATH и зарегистрированные package managers. При обнаружении нескольких исполняемых экземпляров automatic CLI mutation останавливается fail-closed.

На Windows дополнительная ручная read-only проверка:

```bat
where opencode
npm list -g --depth=0 opencode-ai
choco list --limit-output --exact opencode
```

В Chocolatey CLI 2.x `choco list` уже показывает только локально установленные пакеты; удалённый флаг `--local-only` использовать не нужно.

Наличие `@opencode-ai/plugin` под `%USERPROFILE%\.config\opencode\node_modules` в этот список не входит, поскольку пакет не публикует второй managed OpenCode CLI.
