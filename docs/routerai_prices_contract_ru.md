# Проверенный каталог тарифов RouterAI: контракт v1

## Граница публикации

Задача #110 добавляет канал денежных данных для unbazarbot #18 и других клиентов.
Единственный сборщик — существующий `update_routerai_catalog.py`: один GET `/models`
и до 32 последовательных GET `/models/{author}/{model}/endpoints` в том же refresh.
Запросы публичные, без ключей и без инференса. Таймаут каждого — 30 с, ответ — до 16 МиБ.
Набор проверяемых endpoint-моделей и абсолютные денежные пределы задаёт отдельная
ручная `templates/routerai_prices_policy.json`. Она не меняет OpenCode model policy
и не даёт клиенту права вызывать новые модели.

До слияния кода и первого успешного refresh URL может возвращать 404. Отсутствие
канала означает отсутствие опубликованных цен, а не разрешение использовать PR #34.

| Канал | Смысл |
|---|---|
| `main` / generated snapshot | Каталог и конфигурация OpenCode после обычного review |
| `automation/routerai-catalog` | Кандидат; не источник финансового допуска |
| `automation/routerai-status` | Прежний статус, по-прежнему ровно один status JSON |
| `automation/routerai-prices` / `routerai-prices.json` | Независимо опубликованный проверенный денежный документ |

HTTPS URL клиента:

`https://raw.githubusercontent.com/dilukhin/agent-toolchain/refs/heads/automation/routerai-prices/routerai-prices.json`

Документ самодостаточен: данные, контрольная сумма, свежесть и доказательство проверки
получаются одним HTTP-ответом. Отдельного изменяемого manifest и гонки между двумя
GET нет. Предел документа — 8 МиБ. Из GitHub API его можно читать по blob SHA.

## Схема и проверка

Эталонная проверка — `scripts/routerai_prices.py::verify(value, published=True)`.
Полный искусственный пример: `tests/fixtures/routerai_prices_published.json`.

| Поле | Правило |
|---|---|
| `schema` | целое `1` |
| `owner` | `agent-toolchain:routerai-prices:v1` |
| `publisher` | `dilukhin/agent-toolchain` |
| `_managed_notice` | точная константа `NOTICE` валидатора |
| `state` | только `published`; локальный `candidate` потребитель отклоняет |
| `source_url` | только `https://routerai.ru/api/v1/models` |
| `source_checked_at` | UTC `YYYY-MM-DDTHH:MM:SSZ`, нижняя граница свежести всех источников этого документа |
| `snapshot_id` | `sha256:` + SHA-256 канонического `content` в UTF-8 |
| `published_at` | дата успешного продвижения данного документа |
| `content_changed_at` | дата изменения содержания; сохраняется при неизменном hash |
| `validation` | `status=success`, `workflow=validate.yml`, полный `candidate_sha`, числовой `run_id` |
| `content.currency` | `RUB` |
| `content.models` | точный model ID → запись модели, включая непригодные модели |

Канонизация hash: JSON `sort_keys=True, ensure_ascii=False, separators=(",", ":")`,
без NaN и без завершающей новой строки. Все цены и пределы — десятичные строки,
без экспоненты, `float`, отрицательных значений, NaN или Infinity.

Запись модели содержит `id`, `architecture` (модальности), `api`, `status`, `reason`,
`catalog_pricing`, `catalog_pricing_units`, `price_ceilings` и `endpoints`.
Endpoint сохраняет provider tag, точные `pricing` и `pricing_units`,
`supported_apis`, `variable_pricing` и свой точный `source_url`.
Временная деприоритизация провайдера не позволяет убрать его более дорогую цену:
для оценки учитываются **все** перечисленные маршруты, включая резервные.

`available` возможен только при подтверждённом API у всех маршрутов, полном наборе
цен и известных единицах, отсутствии переменной тарификации и соблюдении ручных
пределов для каждого компонента. Иначе `unpriced` с машинной причиной, например
`api-not-confirmed`, `incomplete-pricing-units`, `variable-pricing`,
`unapproved-price-component`, `model-missing` или `endpoints-not-checked`.
Нельзя выводить unit из имени `prompt`, `seconds` или из названия модели.

Не все поля цен суммируются без знания запроса. Клиент обязан сопоставить каждый
положительный компонент с доказанным верхним количеством именно в его единице.
Неизвестное количество токенов или связь между компонентами означает отказ.
Для консервативного резерва предназначены `price_ceilings`, наблюдённые цены
сохраняются отдельно. Денежный предел публикации не гарантирует неизменность
будущей цены у внешнего RouterAI: клиенту нужны собственные ограничения, сверка
фактической оплаты и возможность остановить новую оплату.

## Публикация и защита

1. Fetch/normalize и формирование временного `candidate` из **того же** получения.
2. Проверка производных областей и все Python regression tests.
3. Нефорсированная публикация точного SHA `automation/routerai-catalog`; создание
   или восстановление PR при наличии конфигурационного diff.
4. Полный `validate.yml` для того же SHA даже при отсутствии нового push/diff.
5. `publish_routerai_prices.py` повторно проверяет через GitHub API workflow ID,
   SHA, успешный run и успешные jobs `windows` и `linux`.
6. Проверка владельца прежнего канала: ровно один обычный файл, известные
   schema/owner/notice/publisher, корректный hash и прежняя проверка.
7. Git Data API `blob → tree → commit → ref`, новый commit — потомок прежнего;
   проверка обоих HEAD перед ref, `force=false`, затем чтение дерева/blob назад.

Для первой публикации создаётся отдельная orphan-ветка. Чужая ветка с похожим
именем, дополнительные файлы, symlink, повреждение, неизвестная схема, конфликт
ref, другой SHA кандидата, непройденная проверка или старое наблюдение блокируют
изменение published ref. Успешный retry после потерянного read-back идемпотентен.
Сиротские Git objects после сбоя до ref не являются опубликованными данными.
Между двумя ветками нет транзакции GitHub; проверки HEAD выполняются непосредственно
перед продвижением, а документ всегда содержит именно ранее проверенный SHA.

Обычный merge ежедневного PR конфигурации не требуется. Неизменный каталог
сохраняет hash и `content_changed_at`, но обновляет связанный с ними heartbeat
в специальной ветке; timestamp не создаёт commit в main или PR.

Автоматические permissions не расширены: используются уже существующие
`contents: write`, `actions: write`, `pull-requests: write` refresh workflow.
Публикатор жёстко ограничен одним репозиторием, веткой и файлом; запуск — только
workflow `main`. Проверка hash защищает целостность, но не является цифровой
подписью: владелец доверенного репозитория остаётся доверенной стороной.

## Финансовые пределы и #28

Для первого набора ручные ceilings равны максимальным ставкам провайдеров,
полученным публичным GET endpoint metadata 28.10.2026. Это проверяемые пределы
автопубликации, **не наблюдённые цены** и не статистические пороги аномалий.
Ставки в пределах ceilings могут обновляться автоматически; превышение хотя бы
одного предела останавливает публикацию, last-known-good сохраняется. Повышение
предела требует отдельного осознанного review policy. Это консервативная начальная
политика: рост курса тоже может остановить публикацию, пока предел не пересмотрен.

Общий watchdog, operational issue, анализ потери моделей и относительных скачков
curated-каталога остаются в #28 / PR #78. Они здесь не реализуются повторно.
PR #78 и эта работа меняют общие шаги workflow: при слиянии второго PR необходимо
сохранить его completion contract, восстановление PR/validation и новый шаг prices.
До готовности общего anomaly guard финансовый канал использует строгие собственные
абсолютные пределы. Неизвестные модели не получают денежный допуск автоматически.

Публичные endpoint-данные 28.10.2026 у Whisper содержат `supported_apis: []`.
Это не подтверждает `audio/transcriptions`: запись остаётся `unpriced` даже с
корректной секундной ценой. Не следует обходить отказ ручной подстановкой API.
Один запрос к Qwen ID из шаблона завершился HTTP-ошибкой; сетевые/HTTP ошибки
останавливают текущую публикацию. Получение живых метаданных не было платным тестом.

Официальный источник семантики units/RUB/provider routing:
<https://routerai.ru/docs/guides/overview/provider-selection>.

## Отказы и эксплуатация

| Событие | Published цены | Свежесть и действия клиента |
|---|---|---|
| Fetch/JSON/size/normalization/regression failure | прежний документ | старый `source_checked_at`, затем отказ по возрасту |
| Отсутствуют units/API, переменный тариф | явная `unpriced` запись | новая платная операция запрещена для этой модели |
| Превышен ceiling | прежний документ | исправить источник или отдельно пересмотреть policy |
| PR/validation/ref/ownership failure | прежний документ | `last_attempt.phase/error` в прежнем status channel |
| Источник без изменений и все проверки успешны | тот же hash, новый heartbeat | допустим только heartbeat того же hash |
| Непроверенный новый кандидат | не публикуется | его проверка не освежает старые опубликованные цены |
| GitHub недоступен | локальный last-known-good | допустим до настраиваемого срока; затем только бесплатный кеш |

Ошибка денежной публикации отражается в существующем status как
`phase=publish-prices`, `error.code=price-publication`. Полный сырой ответ не
попадает в status. История price-ветки сохраняет предыдущие версии.

Офлайновая проверка скачанного документа:

```bash
python -c 'import json,sys; from scripts.routerai_prices import verify; verify(json.load(open(sys.argv[1], encoding="utf-8")), published=True)' routerai-prices.json
python -m unittest tests.test_routerai_prices -v
```

При аварии остановить запуски refresh workflow штатными правами GitHub, а у
денежного потребителя заморозить новые платные запросы. Не force-reset ветку
и не править JSON вручную. Для восстановления выбрать прежний проверенный commit
как диагностический last-known-good; старое подтверждение источника не становится
свежим от отката. Исправление — PR к коду/policy и полный новый refresh с проверками.
Ни VPS, ни реальный RouterAI баланс, ни Telegram данным изменением не обновляются.
