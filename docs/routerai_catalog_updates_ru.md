# Обновление каталога RouterAI и `agent-toolchain`

## Назначение

Цены и другие объективные сведения о моделях RouterAI обновляются отдельно от ручной политики выбора моделей.

Ручная политика находится в `templates/routerai_model_policy.json` и определяет:

- какие модели входят в управляемый список OpenCode;
- человекочитаемое имя;
- назначение модели (`основная`, `архитектор`, `код/агент` и т. п.);
- описание;
- прежние управляемые имена, которые можно безопасно заменить.

Объективный снимок RouterAI находится в `templates/routerai_catalog.generated.json`.

Подробное архитектурное объяснение — зачем разделены ручное/производное состояние, как защищается ownership, почему существует отдельная status branch, как сохраняется last-known-good после ошибки и как воспроизвести механизм для другой цели — находится в:

```text
docs/routerai_refresh_status_design_ru.md
```

## Что можно редактировать вручную

| Область | Ручное редактирование |
|---|---|
| `templates/routerai_model_policy.json` | Да. Это ручной source of truth. |
| `templates/routerai_catalog.generated.json` | Нет. Файл полностью генерируется. |
| `config_data.json -> models` | Нет. Раздел принадлежит генератору RouterAI. |
| независимые разделы `config_data.json` | Да, по обычным правилам проекта. |
| `templates/opencode.jsonc -> provider.routerai.models` | Нет. Раздел генерируется. |

В JSON, где это безопасно, генератор добавляет `_managed_notice` с этой политикой, ссылкой на подробную документацию и канонической командой полного ручного запуска.

CI дополнительно проверяет ownership и воспроизводимость, поэтому предупреждение не является единственным предохранителем.

## Автоматическое обновление

`.github/workflows/routerai_catalog.yml` запускается ежедневно и вручную через `workflow_dispatch`.

Процесс:

```text
актуальный main
→ синхронизация automation/routerai-catalog
→ RouterAI GET /api/v1/models
→ нормализация каталога
→ пересчёт цен за 1 млн токенов
→ обновление config_data.json и templates/opencode.jsonc
→ offline generated-state check
→ Python regression tests
→ automation/routerai-catalog
→ pull request
→ полный Windows/Linux validate.yml
→ публикация состояния в automation/routerai-status
```

Для управляемой подписи используются только одновременно присутствующие в `GET /api/v1/models` цены `prompt` и `completion`. Они переводятся из рублей за токен в рубли за 1 млн токенов. Если одной из этих цен нет, старая цена не сохраняется: модель остаётся в управляемом списке, а подпись получает `цена недоступна`. Отдельная цена чтения кэша автоматически не публикуется, пока её контракт не подтверждён публичным источником RouterAI.

Новые модели RouterAI попадают в снимок, но не добавляются в управляемый список автоматически. Если модель из ручной политики исчезла из каталога, сама модель не удаляется: старая числовая цена снимается, подпись получает `цена недоступна`, а workflow печатает предупреждение.

## Штатный ручной запуск полного обновления

Каноническая команда:

```text
gh workflow run routerai_catalog.yml --repo dilukhin/agent-toolchain --ref main
```

Это запускает тот же полный GitHub Actions workflow, который выполняется по расписанию.

Команда предназначена для разработчика/сопровождающего с установленным и авторизованным GitHub CLI и правом запускать Actions репозитория.

Она не является пользовательским обновлением установленного runtime.

## Локальная разработка генератора

Локальная проверка живого RouterAI без записи:

```text
python3 scripts/update_routerai_catalog.py --check
```

Локальная регенерация checkout:

```text
python3 scripts/update_routerai_catalog.py --write
```

Для тестов без сети можно передать сохранённый ответ `GET /api/v1/models`:

```text
python3 scripts/update_routerai_catalog.py --write --input path/to/models.json
```

Это разработческие команды. Они не создают PR и не выполняют полный GitHub workflow.

## Офлайновая проверка производного состояния

```text
python3 scripts/update_routerai_catalog.py --verify-generated
```

Проверка не обращается в сеть.

Она доказывает, что automation-owned области `config_data.json` и `templates/opencode.jsonc` воспроизводятся из:

```text
templates/routerai_model_policy.json
+
templates/routerai_catalog.generated.json
```

Если человек или агент вручную изменил generated area, CI должен упасть с указанием правильного места изменения и команды штатного обновления.

## Канал состояния обновлятора

Текущее машинно-читаемое состояние хранится отдельно от PR:

```text
branch: automation/routerai-status
file:   routerai-refresh-status.json
```

Ветка полностью принадлежит автоматизации. Любые неожиданные дополнительные файлы не усыновляются и не удаляются автоматически.

Статус различает:

- что опубликовано в `main`;
- когда RouterAI последний раз успешно проверялся, даже если изменений не было;
- чем закончилась последняя попытка;
- существует ли более свежий candidate и прошёл ли он полную проверку.

Ошибка последней попытки не стирает предыдущую успешную проверку.

Подробная семантика описана в `docs/routerai_refresh_status_design_ru.md`.

## Что видит пользователь

Управляемые запускаторы OpenCode/Codex используют локальный кэш удалённого RouterAI status и перед запуском показывают короткую русскую сводку.

Нормальный пример:

```text
RouterAI: цены актуальны, каталог проверен 6 ч. назад.
```

Пример после ошибки:

```text
ВНИМАНИЕ: последняя попытка обновить цены RouterAI завершилась ошибкой;
последняя успешная проверка была 1 дн. назад.
Причина последней ошибки: ...
Используются последние опубликованные цены; запуск продолжается.
```

Если в `main` уже есть данные новее локально установленного каталога:

```text
В main уже опубликованы более новые цены.
Обновить установленный toolchain: toolchainctl update --apply
```

Недоступность status channel не блокирует OpenCode/Codex.

## Получение опубликованного обновления на клиенте

Установленный `toolchainctl` получает новый core независимо от developer checkout:

```text
toolchainctl update
toolchainctl apply
```

Одной командой:

```text
toolchainctl update --apply
```

`toolchainctl update`:

1. запрашивает у GitHub точный SHA актуального `main`;
2. скачивает ZIP именно этого SHA;
3. отклоняет небезопасную структуру архива и symlink-элементы;
4. запускает штатный `bootstrap_core.py` из скачанного exact ref;
5. принимает обновление только для уже установленного core с валидным ownership marker;
6. после bootstrap проверяет валидность marker установленного core.

Новые marker дополнительно содержат точный список управляемых файлов и их SHA-256. Поэтому проверка установленной версии не зависит от того, появятся ли в будущей версии новые обязательные файлы core. Marker прежнего формата без этого списка поддерживается как переходный вариант и после первого обновления заменяется новым.

Рабочая копия репозитория для этого не нужна и не изменяется.

## Обновление подписей моделей

`toolchainctl check` только сообщает, если известные управляемые подписи устарели.

`toolchainctl apply` меняет подпись только если текущее имя распознано как одно из ранее управляемых имён. Пользовательское нестандартное имя сохраняется. Остальные поля модели также сохраняются.

Если управляемый `opencode.jsonc` содержит комментарии или trailing commas и для подписи требуется изменение, автоматическое переформатирование не выполняется.

## Диагностика ошибок

В PR и status branch записывается только короткая санитизированная диагностика:

- этап;
- код ошибки;
- краткое описание;
- рекомендация.

Полный stderr/traceback остаётся в GitHub Actions logs.

Это предотвращает случайную публикацию secrets, authorization headers, приватных путей и большого непроверенного вывода.
