# YC59: управляемый выпуск отдельного владельца

`native/yc_owner_managed.ps1` связывает нативную защиту с точным кандидатом
opencode_permissions #72/#73. Манифест в `native/yc_owner_candidate.json`
скопирован без изменения флагов или правил. Источник 16 файлов закреплён на
`1f7d89d9a8cd2352c6df865e8915f66171475972`. Идентичность выпуска:
`sha256:14f643cb899c6bcec43cb2fa417e952d9c9d1a0ba13c5fb6e23a2d1e9e9ea6df`.
Единственный Ledger находится в этом компоненте. Установленная приёмка пока
не выполнена; подготовка и CI не являются согласием на чтение облака.

## Начало доверия

Владелец использует свежий **системный Windows PowerShell 5.1 x64** с
`-NoProfile` в своём отдельном интерактивном входе. Он проверяет опубликованный
внешний SHA-256 seed средствами ОС, читает seed под FileShare.Read в память и
исполняет именно эти байты через ScriptBlock. Повторное исполнение по пути
после проверки недопустимо. Конкретные commit и хеш выдаются в принятом
пакете приёмки. Предполагается доверенная исходная Windows/PowerShell/.NET;
скомпрометированный SYSTEM/администратор не входит в модель защиты.

Seed проверяет точные байты C# **до** Add-Type, затем допускает только разные
обычные локальные учётные записи. SID/SessionId живого клиента читает ОС.
Сеансы из старых отчётов не закрепляются. Пользовательские actor-пробники,
создание пользователей, изменения их групп и существующих ACL не нужны.

## Подготовка и управление

Параметры: Mode, AgentSid, Destination, NativeSource, ManifestPath.
Destination — новый приватный каталог **владельца**, родитель уже существует.
Не выбирать общий профиль Dima или установленное ядро. NativeSource и
ManifestPath могут поступить из недоверенного каталога: до использования
проверяются их закреплённые байты, Python для этого не запускается.

`Prepare` создаёт только новые закрытые каталоги и журнал prepared **до**
загрузки/распаковки. Получает официальный Python 3.14.2 embeddable x64,
официальный YC 1.39.0 windows/amd64 и точные 16 файлов по закреплённому ref.
Источники/размеры/хеши фиксированы, перенаправления и неограниченные загрузки
запрещены. Необязательный Cache содержит только проверяемые байты; это не
источник кода с расширенными полномочиями. При Cache отсутствие файла — отказ,
сетевого запасного пути нет.

Перед публикацией active.json нативный FileLease удерживает все файлы Python,
компонент, YC и предков. Python заново сопоставляется с содержимым закреплённого
официального архива, включая DLL, stdlib и _pth; лишние/изменённые файлы
отклоняются. Компонент сверяется с внешним точным manifest. Состояние становится
complete только после атомарной публикации active.json. Перед сменой сохраняется
контрольная точка предыдущего состояния; каталог прежнего выпуска не удаляется.
Первый выпуск существует параллельно прежнему transitional guard и не меняет
его active/pin/shim/PATH/политику.

Повторный `Prepare` полного выпуска проверяет байты без загрузки; прерванный
prepared не ремонтируется и не перезаписывается. `Check` заново проверяет
журнал/active/полный выпуск без Python и облачных запросов. `Disable` сохраняет
предыдущую запись и выпуск, публикует enabled=false. `Prepare` после штатного
Disable проверяет имеющийся выпуск и активирует его без загрузок. Произвольный
неизвестный выпуск автоматически не усыновляется. Возврат к другим байтам
требует отдельного проверенного pin, а не исполнения неизвестного архива.

Все режимы используют один защищённый глобальный mutex, имя связано с SID
владельца: второй процесс, другой каталог или другой Windows-сеанс того же
владельца не создают параллельную власть. Чужой объект/неизвестный DACL и
обнаруженное прерванное владение вызывают отказ. Во время Run mutex удерживается
до завершения всей группы потомков и освобождения файлов.

## Живой сеанс

`Run` требует настоящую локальную консоль и проверенный активный выпуск.
До Python генерируются новый UUID и путь одноразовой защищённой справки.
Системный администратор выполняет только `AuditAgent` тем же проверенным seed:
читает группы/LSA и атомарно создаёт новый файл с административным владельцем.
Это установочная проверка возможностей агента, не второй владелец разрешений.
Справка связывает текущие SID/UUID и действительна 180 секунд; обычный JSON не
подходит. Группы, привилегии, старые ACL и облако этим шагом не меняются.

После проверки создаются приватные config/cwd, файлы удерживаются; тот же
FileLease.StartPython защищает процесс/токен/default DACL до первой инструкции
Python, задаёт очищенную среду и kill-on-close Job. Ввод IAM-токена (скрыто) и
ID происходит только в защищённой консоли владельца. Токен не записывается в
конфигурацию/журнал/endpoint/отчёт. Оставшиеся согласия после сеанса отменяются,
автоматического восстановления или переноса согласий нет.

Владелец выводит один JSON `yc-owner-live-endpoint/v1`. Агент сохраняет **эту
строку** в свой endpoint.json и запускает штатным Python:

```text
python native/client/request.py --endpoint endpoint.json
```

Клиент использует точные транспортные модули opencode_permissions; это копия
транспорта для недоверенной стороны, без Ledger/решений/исполнителя. Хеши копий
сверяются с авторитетным компонентом тестом. Клиент сверяет настоящий токен
сервера до отправки запроса, получает описание, регистрирует его и ждёт решения.
Публичного approve CLI нет. Согласие даёт только владелец вводом точной фразы
с request ID в своей консоли. Затем клиент вызывает consume **один раз**.
Неизвестный исход/timeout/потеря ответа не повторяются автоматически.

Выбор ID действует 60 секунд; требуется готовый агентский терминал. Согласие
не обновляет наблюдение. При истечении нужен новый выбор/новый сеанс, а не
повтор consume. Результат: ровно три адресных getter, безопасная проекция и
квитанция в консоли владельца. SHA-256 результата у обеих сторон должен
совпасть. Snapshot READY не означает проверенную возможность восстановления.

## Проверки и граница готовности

Изолированный Windows CI использует прежние временные учётные записи стенда.
Выполняет настоящий seed как обычный владелец: Prepare, повтор без чтения Cache,
Check, отказ автоматизированному Run до Python, подмена payload/лишняя DLL,
prepared без ремонта, Disable/повторная активация с контрольными точками и
межпроцессный mutex. Прежние реальные проверки process/token/потомков и контекста
с официальным YC сохраняются. В CI нет IAM-токенов/реальных getters/согласия.

Закрыть #59/#120 можно только после принятого CI и фактической адресной приёмки
на DIMA-HP с реальными ID и квитанцией владельца. Из этой Web-среды нет доступа
к его Windows-консоли; недостающие ID и человеческий ввод нельзя заменить
синтетикой. До результата installed_acceptance остаётся false.
