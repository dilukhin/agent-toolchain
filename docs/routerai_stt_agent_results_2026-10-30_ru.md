## Вывод анализа

По стоимости без длительности/маршрута нельзя подтвердить RUB/second, дублирование
prompt/seconds, округление или минимум. Операционный резерв — не фактическая
длительность. Восстанавливать её из предполагаемой цены, а затем считать это
подтверждением той же цены было бы круговым рассуждением. Повторный запуск
такого же SQL на другом компьютере недостающие данные не восстановит.

Официальные модельные карточки подтверждают API и секундную схему Whisper;
машинное описание по-прежнему содержит неоднозначные prompt/token и seconds/second.
Публичный GET 30.10.2026 также показал, что supported_apis у маршрутов может уже
отсутствовать, а не приходить пустым списком. Это не повод ослаблять общий допуск.
По прямым эндпоинтам Groq/DeepInfra нельзя устанавливать точные правила посредника.

Work проверил вариант с историей RouterAI: get_generation читает метаданные по
ID, но старый бот не сохранял эти ID. Выписка get_statement округляет мелкие суммы
до копеек и не подходит для этой сверки. Новый доступ/MCP/ключи в аккаунте не
настраивались. Источники:
https://routerai.ru/docs/guides/mcp/overview и
https://routerai.ru/docs/guides/overview/multimodal/speech-to-text.md .

## Отдельное разрешение на платные проверки

30.10.2026 владелец разрешил несколько коротких платных запросов в разумных пределах.
Выбран минимальный опыт: три искусственных WAV известной длительности 1,25/9,25/11,25 с,
одна модель, последовательно, без повторов POST. Точная программа и границы —
[RAI-113-PAID-01](tasks/RAI-113-PAID-01_ru.md).

Готовый scripts/probe_routerai_stt_billing.py по умолчанию только показывает план;
--execute явно включает ограниченный опыт. Перед каждой отправкой сверяются
свежие публичные ставки всех маршрутов. Сохраняются точные Decimal usage.cost,
доступные секунды/токены, X-Generation-Id и метаданные generation с проверкой
модели/ID/стоимости. Неизвестный исход, ошибка, несоответствие или превышение
порога 0,10 ₽/ответ останавливают дальнейшие POST. Общий порог следующих вызовов
0,50 ₽; это клиентская остановка, не обещание серверного предела уже отправленного
запроса. После неизвестного исхода автоматического повтора нет.

Звуковой сигнал создаётся в памяти, тексты и ключи не сохраняются; отчёт 0600 в
новом каталоге 0700. Долговечная отметка sending сохраняется до POST; повторное
использование каталога запрещено. Неудачный/незавершённый опыт нельзя продолжить
с другим именем каталога без отдельного решения по уже возможным расходам.

Work выполняет разработку, искусственные проверки, анализ и GitHub. Агенту
остаётся только запуск там, где доступен существующий ключ; Work его не имеет.
Рабочая SQLite и бот в опыте не используются и не изменяются.

#113 остаётся открытой до фактических результатов. Наличие готовой программы
не является утверждением, что платные запросы уже выполнены или тариф подтверждён.
Состояние опубликованного каталога/денежного допуска, ceilings и production
этими репозиторными изменениями не меняются.
