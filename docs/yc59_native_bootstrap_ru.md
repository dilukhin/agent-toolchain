# YC59: проверка защиты до загрузки Python

`native/yc_owner_bootstrap.ps1` и `native/yc_owner_native.cs` образуют нативную
часть подготовки владельца. PowerShell Windows и .NET выполняют проверки до
загрузки Python. Это не источник согласия, не новый approval CLI и пока не
активный YC runtime.

## Начало доверия

Владелец запускает свежий системный Windows PowerShell 5.1 с `-NoProfile` и
проверяет точный опубликованный SHA-256 seed-скрипта средствами ОС. Ожидаемый
хеш должен быть взят из принятой Web-поставки, а не из заявления агента.
Скрипт читается в память под `FileShare.Read`, сверяется с внешним pin и
исполняется из этих же байтов. Проверять Python самим проверяемым Python нельзя.

Внутри проверенного seed закреплён SHA-256 C#-исходника. Только проверенные байты
передаются компилятору .NET. Путь исходника не используется повторно для загрузки
кода; уже загруженный одноимённый тип вызывает отказ и требует свежего процесса.
Системный PowerShell/.NET и ядро Windows — доверенная база выбранного профиля.
Администратор/SYSTEM вне модели защиты; агент с такими возможностями не допускается.

## Субъекты и файлы

Нативная проверка получает локальную учётную запись по SID через ОС, читает
прямые и косвенные группы `NetUserGetLocalGroups`, проверяет наличие Users и
отсутствие административных/операторских групп. Это дополняет runtime-проверку
токена: отфильтрованный токен не скрывает административную учётную запись.

Windows CI подтвердил, что обычный владелец не может читать все назначения
привилегий LSA. Эти сведения не пропускаются и не заменяются токеном клиента.
Для них введён одноразовый читающий шаг администратора `AuditAgent`: та же
закреплённая нативная программа проверяет LSA пользователя и всех его групп.
Она не меняет группы, привилегии, существующие ACL и не создаёт службу.
Администратор этого шага — доверенная установочная роль ОС, не второй владелец
согласий: доступа к Ledger или выдачи облачного допуска у него здесь нет.

Обычный владелец генерирует новый UUID, ожидает защищённую справку до 180 секунд
и проверяет SID агента/владельца, UUID и свежесть. Справка создаётся новым файлом
с владельцем Administrators и доступом только System/Administrators и владельцу
на чтение. Публикация атомарна, файл не перезаписывается. Проверка требует
именно административного владельца файла, обычный JSON/файл владельца не подходит.
Эта справка относится к допуску учётной записи в доверенной исходной ОС; она
не доказывает отсутствие уже произошедшей компрометации Windows, не является
человеческим согласием и не предоставляет права исполнения облачной операции.
Недоступные сведения вызывают отказ, права/группы автоматически не меняются.

Проверка файлов открывает обычные локальные объекты ядра и удерживает их
дескрипторы до окончания использования. Сверяются фактический путь, владелец,
DACL и тип объекта; reparse points и файлы с несколькими жёсткими ссылками
отклоняются. Права записи, удаления и изменения защиты для недоверенных
субъектов запрещены. Для предков проверяется возможность подмены/удаления
существующего потомка, для самого дерева — также внедрение новых файлов.
Дескрипторы разрешают только совместное чтение: известный файл нельзя заменить,
переписать или удалить во время lease; нельзя переименовать удерживаемый предок.

Проверки ограничены локальными обычными путями, 10000 файлов, 256 МиБ на файл и
512 МиБ суммарно. Неподдержанные ACL не интерпретируются по догадке.

## Python и ограничения текущего компонента

`PreparePython` создаёт только **новый** закрытый каталог владельца с DACL,
заданным при атомарном `CreateDirectoryW`. Существующий каталог не усыновляется,
его права не исправляются. Журнал `prepared` сохраняется при ошибке; повтор
не ремонтирует частичную поставку.

Закреплён официальный встраиваемый Python 3.14.2 x64: URL и SHA-256 взяты из
[официального SBOM Python](https://www.python.org/ftp/python/3.14.2/python-3.14.2-embed-amd64.zip.spdx.json).
Архив проверяется до распаковки и до исполнения; распаковка допускает только
обычные уникальные плоские имена с ограничением объёма. Общий `C:\Python314`
не изменяется. Подготовка не запускает Python, YC или облачные операции.

`FileLease.StartPython` запускает только уже удерживаемый `python.exe` с
фиксированными `-I -S -B`, удерживаемыми entry/config и защищённым cwd.
Вызов разрешён только обычному отдельному владельцу в ненулевом сеансе.
Процесс создаётся приостановленным с закрытыми DACL процесса/потока; до
первой инструкции Python закрывается его токен и назначается Windows Job.
Агенту оставлены только запросы личности процесса/токена. Запись памяти,
инъекция потока, дублирование/изменение токена, остановка процесса и изменение
DACL запрещены точному SID. Защита применяется также к нативному родителю.
До ResumeThread в токене Python задаётся закрытый TokenDefaultDacl: новые
процессы/потоки/объекты получают права только владельца/System/Administrators,
с явным запретом SID агента. Это закрывает окно доступа к будущему дочернему YC
до выполнения его первой инструкции. CI отдельно пытается открыть созданного
через обычный Popen потомка, включая identity query: доступ агента отклоняется.
Это права отдельных объектов ядра, существующие файловые ACL не меняются.

Окружение создаётся заново из пяти значений: SystemRoot, системный PATH,
TEMP/TMP/USERPROFILE в защищённом cwd. Дескрипторы не наследуются. Windows Job
ограничивает число процессов восемью и общую память 1 ГиБ; завершение родителя,
освобождение lease или timeout убивают всю группу, включая потомков. Сначала
завершается группа, затем освобождаются файлы интерпретатора/кода/конфигурации.
Ожидание ограничено 10 минутами. Владелец не получает административных прав.

Этот слой пока не запускает прикладной owner и не удостоверяет native veto или
ReadContext. Для рабочего пути ещё требуются защищённая активация, подключение
доверенных источников и конкретный профиль запуска. Windows CI проверяет
настоящие файловые запреты и запускает только точный официальный Python со
статической проверкой версии и очищенным окружением. Дополнительно отдельный
обычный владелец запускает защищённый процесс, другая учётная запись проверяет
отказы записи/управления и дублирования токена. Проверяются timeout и гибель
потомка при закрытии группы. Никакое действие человека
или готовность установленного DIMA-HP этим не доказываются.

Источники: [NetUserGetLocalGroups](https://learn.microsoft.com/en-us/windows/win32/api/lmaccess/nf-lmaccess-netusergetlocalgroups),
[LsaEnumerateAccountRights](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-lsaenumerateaccountrights),
[FileShare](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare?view=netframework-4.8.1).


## Управляемый выпуск

`native/yc_owner_release.ps1` содержит точные байты C# и авторитетного v2-манифеста
внутри независимо проверяемого seed. Prepare/Check/Run работают под владельцем;
на входе Run WTS подтверждает собственный интерактивный вход (runas недостаточно)
до запроса секретов. Родитель запечатывается сразу после загрузки нативного слоя.
Общий owner.lock в защищённом профиле охватывает все выпуски/сеансы этого SID.
Журналы и контрольная точка не содержат согласий; прошлый выпуск сохраняется.
Неподтверждённый прежний процесс и частичный журнал вызывают отказ.

CI проверяет настоящий цикл Prepare/Check, повторную подготовку, общий замок,
сохранение прошлого выпуска, отказ частичному журналу и фоновому Run. Введённый
в тесте закрытый checkpoint — только испытание поставки, не имитация согласия
или облачного результата. Подробная локальная приёмка — [отдельная инструкция](yc59_managed_delivery_ru.md).
