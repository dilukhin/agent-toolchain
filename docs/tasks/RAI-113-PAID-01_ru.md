# RAI-113-PAID-01: три коротких искусственных запроса для сверки тарификации

Дата: 30.10.2026. Связь: agent-toolchain #113, unbazarbot #24.
Владелец в этом диалоге разрешил несколько коротких платных запросов в разумных
пределах. Work сузил разрешённый опыт до трёх запросов, перечисленных ниже.
Это отдельное поручение на исследовательские вызовы; обновление бота не разрешено.

## Что уже сделано в Work

Получены и проверены результаты RAI-113-ARAGORN-01: 39 строк, 30 пригодных
наблюдений, 9 пропущенных, фактическая длительность отсутствует во всех 30,
операционный резерв есть у 9. Суммы legacy REAL, маршрут неизвестен. Вывод
о RUB/second из этой выборки сделать нельзя. Повторять чтение SQLite не нужно.

Готовый scripts/probe_routerai_stt_billing.py создаёт WAV в памяти и выполняет
все проверки. Публичный поиск, код, тесты, GitHub и последующий анализ выполняет
Work. Локальному агенту нужен только запуск там, где имеется рабочий ключ;
этот ключ Work недоступен. Ничего разрабатывать и устанавливать не требуется.

## Разрешённый объём

| Параметр | Значение |
|---|---|
| Модель | Только openai/whisper-large-v3-turbo |
| Платные попытки POST | Не более 3, строго последовательно, без повторов |
| Вход | Искусственный звуковой сигнал, WAV PCM16 mono 16000 Hz |
| Известные длительности | 1,25; 9,25; 11,25 секунды |
| Суммарная длительность | 21,75 секунды |
| Порог остановки после одного ответа | 0,10 ₽ |
| Общий порог остановки следующих запросов | 0,50 ₽ |
| Перед каждым POST | Публичные цены всех маршрутов; проверка ожидаемой формы цен и исследовательского конверта 60 секунд по максимальной ставке <= 0,10 ₽ |
| После POST | usage.cost/seconds/токены, X-Generation-Id, до двух GET метаданных той же генерации |

Пороги действуют в испытателе: они не ограничивают стоимость уже отправленного
запроса на сервере RouterAI. После неожиданной цены, расхождения сумм, отсутствия
цены/идентичности, ошибки или неизвестного исхода программа прекращает опыт.
Конверт 60 секунд — предосторожность опыта, не установленный тарифный минимум.
Тоны проверяют расчёт, а не качество распознавания речи. Нулевой/пустой текст
не мешает сохранить числовые сведения; сам текст в отчёт не попадает.

## Единственная работа агента

1. На доступном aragorn либо dima-hp использовать уже доверенный канал
   ssh_relay vserv, если подтверждённый рабочий ключ находится только на сервере.
   Подтвердить узел, существующий Python 3.10+ и путь EnvironmentFile.
   Не печатать файл/окружение целиком, не копировать ключ на другую машину.
2. Получить готовый scripts/probe_routerai_stt_billing.py из указанного Work
   проверенного коммита, UTF-8/LF без изменения байтов. SHA-256:
   `5d0f5e82ebd054e676e97ce7dcb33c18e5c50cff01c5046bdcb73b06420aec2d`.
   Разместить отдельно от приложения/выпусков, в закрытом исследовательском каталоге.
3. Один раз запустить существующим Python. Показанные ниже пути условны:

```text
python probe_routerai_stt_billing.py --execute --env-file ПОДТВЕРЖДЁННЫЙ_BOT_ENV --run-dir НОВЫЙ_КАТАЛОГ_ИССЛЕДОВАНИЯ/RAI-113-PAID-01
```

   Родительский каталог должен существовать. Сам run-dir ещё не должен
   существовать: его исключительное создание — защита от случайного повтора.
   Допускается уже установленная переменная ROUTERAI_API_KEY вместо --env-file;
   значение ключа не передавать аргументом команды и не выводить.
4. Вернуть report.json и короткий отчёт: проверенный узел/канал, SHA скрипта,
   число платных попыток, итоговый статус и известный суммарный расход.
   Отчёт не публиковать в GitHub автоматически. После любого остановленного
   исхода не удалять каталог, не повторять --execute и не менять run-dir ради
   нового запуска. Вернуть сохранившийся отчёт, дальнейшее решение примет Work.

Без --execute программа только показывает план, без сети и чтения ключа.
Агенту не поручается повторять разработку/тесты/публичное исследование.

## Границы

Используется существующий ключ только внутри процесса для HTTPS к routerai.ru;
перенаправления запрещены. Никаких новых ключей/MCP/OAuth, изменений баланса,
службы, systemd, BotFather, config, SQLite, тарифного кеша, рабочих разрешений
или обновления бота. SQLite в этом опыте вообще не открывается. Telegram не
вызывается. Аудио — искусственное, создаётся в памяти; пользовательские файлы
и расшифровки не используются. В отчёт попадают только числовые метаданные,
модель/провайдер, безопасный ID собственной тестовой генерации, размеры/хеши.
Поля generation_time/latency не трактовать как длительность аудио.

При проблеме доступа не обходить действующие ограничения канала/прав.
Финансовый допуск в опубликованном каталоге и настройки бота этим опытом
не меняются. Анализ и последующее решение по нормализации выполнит Work.
