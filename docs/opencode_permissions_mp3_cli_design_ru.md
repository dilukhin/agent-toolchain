# MP-3: явное управление P0

Статус: проект интерфейса для agent-toolchain#61; не свидетельство готовности к включению на пользовательской машине.

## Граница

`toolchainctl p0 enable|disable|status|metrics` — отдельный opt-in путь. Обычные `check`, `apply`, `update --apply` его не вызывают. Установщик пользуется существующим `setup_opencode_permissions_pilot`, не переписывает policy и не принимает `trusted=true`.

| Команда | Ввод | Результат |
|---|---|---|
| `enable` | Зафиксированный источник P0 и фактический `opencode --version` | Проверка до записи, затем существующая транзакция `prepared → active`; повтор с тем же источником — no-op |
| `disable` | Запись владения и сохранённые исходные артефакты | Снятие только совпадающего loader и восстановление только собственного изменения config; версия OpenCode могла измениться |
| `status` | Локальная запись владения и фактические файлы | Только чтение: `disabled / prepared / active / conflict`, без создания каталогов |
| `metrics` | Агрегированные снимки для одного точного артефакта | Только чтение; группировка по версии, profile и artifact; отсутствие данных явно обозначается |

Сырые команды, пути целей, аргументы, окружение и идентификаторы сессий в вывод метрик не попадают.

## Источник и пути

Источник policy — неизменяемый commit `dilukhin/opencode_permissions` с заранее принятой парой идентификаторов pilot/native artifact. Скачивание выполняется только при явном `enable`, в отдельную временную область; manifest, файлы и взаимные ссылки проверяются `validate_artifacts` до публикации локальной копии. Не выбирается «последний» каталог `dist`, не допускается произвольный branch HEAD или ближайшая версия. Для нового exact OpenCode target требуется новый profile, артефакт и проверка совместимости.

Локальная копия обоих источников должна оставаться доступна для отключения без сети. Её содержимое повторно проверяется при отключении. Существующая или изменённая неизвестная копия вызывает конфликт и сохраняется. Канонические config/data/state выводятся из установленного пользовательского окружения; произвольный путь к registry или runtime не поступает от модели.

## Предварительная проверка

Перед первым изменением `enable` проверяет Linux, фактическую версию executable, exact deployable profile и digest обеих частей, известное владение global plugin/config и recovery payload. Затем проверяются применимые слои разрешений для выбранного рабочего каталога: global, custom environment, project/.opencode, agent overrides, plugins и управляемые настройки. Неизвестный слой или конфликт прекращает включение до записи. Текущая документация OpenCode перечисляет эти слои, но их поведение для 1.18.29/нового target подтверждается отдельно точным runtime-профилем.

Глобальный loader может действовать в другом проекте после первоначального включения. Поэтому проверка только текущего каталога не доказывает безопасность всех будущих запусков. До live pilot нужен один из двух проверенных контрактов: ограничение действия loader тем же проверенным workspace при каждом разрешении либо изолированное применение только к запускаемому pilot-процессу. Выбор подтверждается disposable exact OpenCode run; это условие включения, а не косметическая проверка интерфейса.

## Отключение после обновления

Проверка совместимости новой версии нужна для включения, но не для снятия собственного loader. При `disable` исходные артефакты сопоставляются с версией и идентификаторами из записи первоначальной установки. Проверки состояния, путей, plugin/config digest и фазы выполняются до удаления. Чужой изменённый файл остаётся без изменения, команда возвращает conflict. `prepared` после прерывания тоже можно безопасно откатить. Откат версии OpenCode не требуется.

## Снимки метрик

Считываются только `process-<pid>.json` из реального `$HOME/.local/state/opencode_permissions/p0-metrics/<artifact-segment>/`. Неизвестная схема, иной profile/version/artifact, неверные счётчики, повреждение, ссылка или смешанные снимки дают явную ошибку. Повторное чтение одного и того же snapshot не суммируется как новое событие. PID reuse может перезаписать прежний snapshot: отчёт описывает текущую сумму снимков, а не полный исторический счётчик.

`native_allow/native_deny` не вычисляются. При `native_ask=0` доля сокращения подтверждений не определена. `binding_reject` и ошибка исполнения не считаются успешной автоматизацией.

## Приёмка

Временные фикстуры: `enable → status → повторный enable → metrics → disable`, отсутствие/повреждение состояния и метрик, чужие plugin/config, отказ записи, `prepared`, смена версии перед отключением, неизвестная версия/платформа/digest и competing layer. Затем MP-1, MP-2 на точном новом head и проверка отсутствия `unsafe automatic allow`. Пользовательская машина остаётся вне этих испытаний.
